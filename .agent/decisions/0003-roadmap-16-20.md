# 0003 · Roadmap: phases 16–20 (proposal, needs the owner)

**Context.** The owner said Toccata (15) is the last phase that adds features for a while and that
major changes are coming. So 16–20 make MusicForge solid, give it its own identity and ship 1.0.
New features only enter where a phase below says so. Each phase still ends with a from-scratch
review before it is confirmed (owner's rule), and ships as `0.N.x` updates in between.

**Before 16 starts: Toccata 0.15.x.** P2…P8 close every gap from `docs/AUDIT-0.15.md` (the
reference-app audit), every pixel bug from the emulator walk-throughs and the motion language in
`0002-motion-language.md`. That is where "everything a user could want" lands.

| Phase | Working theme | What it is | Owner decides |
|---|---|---|---|
| 16 | **Identity** | A real name, icon, colour and signature element; the launcher label stops being a codename; rename the vendored `com.metrolist.innertube` package; site and README follow | the name, the look, whether the codename habit stays for releases |
| 17 | **Hardening** | StrictMode-clean, no main-thread I/O anywhere, crash and ANR budget with on-device measurements (start, scroll, player open) on the X7b, baseline profile refreshed, Room migration tests for every version, fuzzed backup import | the performance targets |
| 18 | **Accessibility and language** | TalkBack pass on every screen, font scaling to 200 %, contrast, reduced motion, RTL; string resources and the first translations | which languages |
| 19 | **Platforms** | Android Auto polish, widgets (sizes, Material You), lock-screen and Bluetooth metadata, optional Wear OS / TV (BitChord has both) | Wear OS and TV in or out |
| 20 | **1.0** | Release candidate: frozen features, full regression run on device and emulator, F-Droid / IzzyOnDroid metadata, user docs, stable channel in the updater | where 1.0 is published |

**Rules out.** New subsystems without an owner decision; Material screens; anything that costs
the X7b frame budget.
