## Critical

### TheSet.kt:188-192 — Per-frame recomposition via `mutableLongStateOf` in `LaunchedEffect`
**File:line** `ui/forge/TheSet.kt:188-192`
**Failure scenario** During an active Automix blend, the `while(true) clock = withFrameNanos { it }` loop updates a `mutableLongStateOf` every frame. `mutableLongStateOf` writes invalidate the snapshot, triggering full recomposition of the `Seam` composable (and its LazyColumn parent) at 60–120 fps. On the target X7b (Snapdragon 680) this will drop frames, heat the device, and drain battery.
**Suggested fix** Replace `mutableLongStateOf` + `while(true)` with an `Animatable` driven by a finite spec, or read frame time directly in `drawBehind` via `DrawScope`'s implicit frame clock (e.g., `AnimationClockObservable` or a custom `MonotonicFrameClock` tied to the blend's beat). The comment claims "read in drawBehind only" but the state write defeats that.

### Scrubber.kt:250, 293-348 — Per-frame recomposition via `mutableFloatStateOf` in `MixPulse`
**File:line** `ui/player/Scrubber.kt:250` (`level`), `293-348` (`rememberMixPulse` loop)
**Failure scenario** The `MixPulse.level` (`mutableFloatStateOf`) is updated every frame in a `while` loop inside `LaunchedEffect`. `Scrubber` calls `pulse.alpha(1f)` during composition, which reads `level` — registering a snapshot dependency. Every frame write to `level` invalidates `Scrubber` composition. The "Mixing" label and fill alpha animate smoothly but at the cost of 60+ recompositions/sec.
**Suggested fix** Move all pulse state into `Animatable`/`animate*AsState` driven by the beat clock, or compute the pulse entirely in `drawBehind` using a frame callback (`LaunchedEffect` with `withFrameNanos` that writes to a `graphicsLayer`/`drawBehind`-only `Animatable`). Never write `mutableStateOf`/`mutableFloatStateOf` in a per-frame loop.

## High

### LocalAudioScanner.kt:163-191 — Presence query uses wrong selection (filters by `DATE_MODIFIED` cutoff)
**File:line** `data/local/LocalAudioScanner.kt:165-170`
**Failure scenario** The presence query (lines 165-170) reuses `baseSelection` and `baseArgs` which include `DATE_MODIFIED >= ?` (the incremental cutoff). This means the "what files exist now" query only sees files modified since the last scan. Files older than the cutoff but still on disk are treated as missing → `listingComplete` stays true → `idsToRemove` deletes them. User loses library entries for untouched files.
**Suggested fix** The presence query must use the unfiltered `baseSelection` (IS_MUSIC/MIME_TYPE + duration + MusicForge folder exclusion) without the `DATE_MODIFIED` cutoff. Create a separate `presenceSelection` = `baseSelection` + `baseArgs` (no cutoff clause).

### Scrubber.kt:218-220 — "Mixing" label touch target < 48dp, missing semantics
**File:line** `ui/player/Scrubber.kt:218-220`
**Failure scenario** The "Mixing" `Text` is clickable (TODO: open mix view) but has no `contentDescription`, no `role = Role.Button`, and its touch target is the text bounds (~14sp height × text width). On a 360dp wide screen the label is ~60dp wide × 20dp high — fails WCAG 2.5.5 (48×48dp minimum). TalkBack announces only "Mixing" with no button role.
**Suggested fix** Wrap in a `Box` with `Modifier.minimumInteractiveComponentSize()` (48dp), add `semantics { role = Role.Button; contentDescription = "Open mix view" }`, keep the graphicsLayer alpha animation.

### LocalMusicScreen.kt:126-140 — `ScanButton` touch target < 48dp
**File:line** `ui/screens/LocalMusicScreen.kt:126-140`
**Failure scenario** `ScanButton` uses `padding(horizontal = 10.dp, vertical = 7.dp)` around `labelMedium` text ("Scan" ≈ 36dp wide). Total clickable area ≈ 56dp × 28dp — height well under 48dp. Fails accessibility minimum touch target.
**Suggested fix** Use `Modifier.minimumInteractiveComponentSize()` or `size(minWidth = 48.dp, minHeight = 48.dp)` on the clickable Box, center the text inside.

### ForgeDock.kt:178-180 — Tab icon `contentDescription = null` on selectable tabs
**File:line** `ui/forge/ForgeDock.kt:178-180`
**Failure scenario** `DockTabs` renders `Icon(tab.icon, contentDescription = null, ...)` inside a `selectable(role = Role.Tab)`. The tab's accessible name comes from the `Text(tab.label)` sibling, but the icon is a separate focusable element (via `selectable` interaction source) with no description. TalkBack may announce "Unlabeled, tab" for the icon area.
**Suggested fix** Remove `contentDescription = null` (default is good) or set `contentDescription = tab.label` on the icon, and mark the icon as `importantForAccessibility = No` if the parent `selectable` already provides the label.

### TheSet.kt:135-137 — `LaunchedEffect(queue)` rebuilds `rows` on every queue emission, losing scroll position
**File:line** `ui/forge/TheSet.kt:135-137`
**Failure scenario** `LaunchedEffect(queue)` clears and rebuilds the entire `rows` `mutableStateListOf` on every queue change (including Automix progress updates). `LazyColumn` keys are stable (per-mediaId), but the list replacement forces a full diff and can reset scroll position if the first item changes. Automix updates `queue` flow frequently during blend.
**Suggested fix** Derive `rows` directly from `queue.drop(first)` in a `derivedStateOf` or `map` on the flow, avoiding the `LaunchedEffect` mutation. Keep stable keys; let Compose diff.

## Medium

### LocalMusicViewModel.kt:148-165 — `scan()` reads settings with `.first()` (blocking) on IO dispatcher but called from viewModelScope (Main)
**File:line** `ui/screens/LocalMusicViewModel.kt:148-152`
**Failure scenario** `graph.settings.data.first()` is a suspend call that blocks until the first DataStore value emits. Called from `viewModelScope.launch` (Main dispatcher by default). If DataStore is slow (disk I/O), this blocks the main thread briefly. Not ANR-level but violates "nothing heavy on main thread".
**Suggested fix** Wrap the settings read in `withContext(Dispatchers.IO)` or use `.map { it[Keys...] }` on the flow and collect in the launch.

### MixView.kt:467-470 — `WaveColorCache` never evicts, unbounded growth
**File:line** `ui/player/MixView.kt:467-470`
**Failure scenario** `ConcurrentHashMap` cache stores `WaveColors` per artwork URL forever. Long sessions with many blends (e.g., party queue) accumulate entries. Each entry holds three `Color` objects — small but unbounded.
**Suggested fix** Use `LruCache` (max 50 entries) or `LinkedHashMap` with `removeEldestEntry`. Two covers per blend, a handful per session — 50 is generous headroom.

### ForgeRoot.kt:163-166 — Sync failure toast uses `LaunchedEffect(context)` collecting flow on Main
**File:line** `ui/ForgeRoot.kt:163-166`
**Failure scenario** `context.graph.library.syncFailures.collect { Toast.makeText(...) }` runs on the `LaunchedEffect`'s dispatcher (Main). If the flow emits rapidly (many failed writes), toasts queue and UI thread churns. Also, `Toast` from background flow can leak if composition disposes mid-show.
**Suggested fix** Collect on `Dispatchers.IO` (or `Dispatchers.Default`), `withContext(Main) { Toast... }` per emission, or use a `SnackbarHost`/`Snackbar` tied to the scaffold (but root has no host yet — comment acknowledges this).

### Slider.kt:44 — Slider track height 44dp < 48dp minimum touch target
**File:line** `ui/designsystem/Slider.kt:44`
**Failure scenario** `Canvas(modifier.fillMaxWidth().height(44.dp))` — the entire drag/tap area is 44dp tall. Material 3 and WCAG require 48dp minimum. User with motor impairment may miss the drag zone.
**Suggested fix** Change to `height(48.dp)` (or 56dp for comfort). The thumb is 22dp (11dp radius × 2), centered — 48dp gives 13dp padding top/bottom.

### Sheet.kt:106 — Drag handle 36×4dp, no semantics for drag gesture
**File:line** `ui/designsystem/Sheet.kt:106`
**Failure scenario** The sheet drag handle is a 36dp×4dp visual bar. No `contentDescription`, no `semantics { role = Role.Button; ... }`, no `draggable` state for accessibility services. Screen readers cannot discover "drag to dismiss".
**Suggested fix** Add `semantics { contentDescription = "Drag to dismiss sheet"; role = Role.Button; onClick { close(); true } }` (click as fallback) and `draggable = true` hint.

### Menu.kt:84-85 — `PopupProperties(focusable = true)` but no focus trap / initial focus
**File:line** `ui/designsystem/Menu.kt:84-85`
**Failure scenario** Menu opens as a `Popup` with `focusable = true` but no `PopupProperties(enterTransition/exitTransition, focusable = true, dismissOnBackPress = true, dismissOnOutsideClick = true)`. Focus may not land on the first item; Tab navigation can escape the menu. Keyboard/switch users get stuck.
**Suggested fix** Add `PopupProperties(focusable = true, dismissOnBackPress = true, dismissOnOutsideClick = true)` and ensure the `Column` content has `Modifier.focusTarget()` or use `FocusRequester` to request focus on first item in `LaunchedEffect(expanded)`.

## Low

### LocalAudioScanner.kt:150 — `existingIds.add(contentUri)` inside cursor loop mutates set used for cutoff logic
**File:line** `data/local/LocalAudioScanner.kt:150`
**Failure scenario** The `existingIds` set is initialized from `dao.localSongIds()` (line 64). During the upsert loop, new songs not in DB are added to `existingIds` (line 150). This means a file appearing twice in MediaStore (duplicate URI) would be treated as "existing" on second occurrence and skipped. Harmless (MediaStore URIs are unique per file) but confusing mutation of the "pre-scan" snapshot.
**Suggested fix** Use a separate `seenInThisScan` set for deduplication within the scan, leave `existingIds` as the pre-scan baseline.

### ForgeRoot.kt:209-214 — `selectTab` lambda captures `route` and `nav` but `route` is from `nav.currentBackStackEntry?.destination?.route`
**File:line** `ui/ForgeRoot.kt:209-214`
**Failure scenario** `route` is captured at composition time. If a navigation transition is mid-animation and user taps another tab, `route` may be stale (previous route). The `if (route == tab.route)` check could misbehave. Low risk — taps during transition are rare and `launchSingleTop`/`popUpTo` handle it.
**Suggested fix** Read `nav.currentBackStackEntry?.destination?.route` inside the lambda (snapshot it at click time).

### TheSet.kt:247-249 — `SeamKind.Analysis` renders "Analysing…" / "Couldn't analyse" but no accessibility live region
**File:line** `ui/forge/TheSet.kt:247-249`
**Failure scenario** Analysis state changes (WAITING → ANALYSING → READY/FAILED) update the seam text. No `LiveRegion` semantics → TalkBack doesn't announce changes. User relying on screen reader won't know analysis completed/failed.
**Suggested fix** Wrap the analysis state `Text` in `semantics { liveRegion = LiveRegionMode.Polite }`.

### MixView.kt:580-585 — `MixViewOverlay` uses `delay(240)` to keep `held` view through close animation
**File:line** `ui/player/MixView.kt:580-585`
**Failure scenario** Hardcoded 240ms delay must match `AnimatedVisibility` exit duration (220ms + margin). If animation duration changes (e.g., `Motion` tokens), the delay desyncs and `held` clears early/late.
**Suggested fix** Use `Animatable`/`AnimationState` callback or `LaunchedEffect` on `visible` to clear after exit animation completes, or share the same `tween(220)` spec.

### Slider.kt:72 — `Physics.shapeSlider` / `Physics.flingTarget` / `Physics.stretchFor` — external physics functions not visible in diff
**File:line** `ui/designsystem/Slider.kt:72, 78, 89`
**Failure scenario** Behavior depends on `Physics` object (from `dev.musicforge.ui.designsystem.Physics`). If those functions have bugs (e.g., fling target exceeds bounds, shape clamps wrong), the slider misbehaves. Not verifiable from this diff alone.
**Suggested fix** Ensure `Physics` has unit tests covering slider edge cases (fling past ends, zero velocity, max steps).

### Experience.kt:1-20 — `Experience` enum stored by name in DataStore; no migration if enum changes
**File:line** `ui/Experience.kt:1-20`
**Failure scenario** `Experience.of(stored: String?)` matches by `name` (CLASSIC/FORGE). If a future version renames or adds values, old stored strings map to `CLASSIC` silently. No versioning/migration.
**Suggested fix** Store ordinal or a stable string key ("classic"/"forge"), add migration logic in `Prefs`/`Keys` when schema evolves.
